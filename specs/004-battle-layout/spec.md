# Spec 004：战斗布局与叠放手牌

状态：Accepted（2026-11-21 最新Web包验收通过，用户明确授权“提交004并push”）
上游：constitution.md C-1/C-3/C-4/C-6、§4/§6/§7；002-battle-art；003-central-config
范围：战斗页表现与指针交互，及选角色/战后选牌页的共用美术展示，不修改玩法。

## 1. 目标

改善人物与背景融合：角色站在可见地面上，背景保持原图颜色；生命与护盾以条形和数字表达；手牌叠放，鼠标悬停时展开单张牌。

## 2. 非目标

不改生命、格挡上限、伤害、能量、抽牌、卡组、存档、玩法配置默认值；不制作新人物动画、出牌飞行、受击粒子、音效或终版美术；不调整地图和结算页；组队及奖励页仅同步美术，选择规则不变；不提交或推送Git，除非另获授权。

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 两人和三人队伍、普通怪和魔王的脚底落在背景可见地面，不再悬在上部面板中；保持敌左我右、人物朝向及阵亡辨识。 |
| FR-2 | 移除覆盖人物的常驻面板底色，保留必要的目标提示；脚下有轻量落地阴影，不遮挡生命条或手牌。 |
| FR-3 | 战斗背景使用原图颜色，不施加全局灰暗滤镜；信息保持可读。 |
| FR-4 | 人物及敌人生命使用进度条和当前/最大数字；队友护盾使用单独条形与精确格挡数字，零值可辨认。条形显示不改变玩法上限。 |
| FR-5 | 默认手牌有可见重叠，右侧牌覆盖左侧牌；所有牌均可通过露出区域访问。 |
| FR-6 | 鼠标悬停单张牌时该牌突出展开，可完整阅读名称、费用和效果；移出后恢复叠放。悬停不等于选牌，不耗能、不写存档。 |
| FR-7 | 重叠处点击作用于视觉最上层牌；悬停牌、选中牌和不可用牌的区别明确。快速跨牌移动不闪烁或误触。 |
| FR-8 | 出牌、结束回合、读档、离开战斗与销毁后清理悬停表现，不将旧索引或旧牌误认为当前牌；原点击目标、取消与快捷键仍有效。 |
| FR-9 | 图片加载失败仍可使用生命/护盾显示与文字牌，叠放和悬停交互可用。 |
| FR-10 | 红、绿、蓝、白四色能量集中显示在战斗页左下角，图标配精确数字；白色使用用户提供的energy_white素材，不能遮挡手牌或目标。图片失败时保留四色数字回退。 |
| FR-11 | 移除战斗页与手牌上的常驻选牌操作提示，保留选中视觉状态、能量不足和无效操作反馈；其他页面提示与战斗交互不变。 |
| FR-12 | 使用用户提供的同名_1新图替换三名角色、普通怪和魔王；原图独立归档可恢复，保持现有资源引用；除后续明确授权的卡框替换（FR-16）外，不替换其他素材或改变玩法。 |
| FR-13 | 后续人物与怪物原始素材统一朝左；战斗页人物位于右侧朝左，普通怪和魔王位于左侧朝右。怪物朝向通过运行时水平镜像实现，不翻转原图或文字/状态条。 |
| FR-14 | 通过整理人物/怪物素材及导入设置，清理近透明残留、将脚底/史莱姆身体底部置于图片底部中央，使既有落地阴影与主体对应；不引入独立接地点定位机制，保留人物造型、颜色及朝向，调整前素材可恢复。 |
| FR-15 | 人物和怪物均可独立配置显示高度，调整高度时保持等比、不因宽度或透明留白而被额外缩小；脚底、朝向、生命/护盾和玩法不变。绿色骑士默认比红、蓝人物更高，身份文字不遮挡头部；不配置高度时兼容既有显示。 |
| FR-16 | 用用户确认的加宽、增高并上移名称栏版本替换原卡框素材；旧素材可恢复，保持现有资源引用，卡框其余区域及玩法不变。 |
| FR-17 | 卡名动态显示在卡框中间名称栏内；左上角显示所需能量类型图标，费用数字置于图标中央；费用视图支持多项从上往下排列，不遮住卡名或效果。现有单色卡仅显示一项真实颜色费用，白色补足不作为额外要求；多类型实际费用规则不在本任务引入。图标失败仍可辨认颜色和费用，悬停/选中/不足状态及资源释放有效。 |

| FR-18 | 选角色页使用当前三名角色立绘，保持配置信息、选择顺序和确认/继续规则；战后选牌页复用新卡框、中部卡名与能量费用图标。两页展示可读、点击有效，图片失败回退文字，切页及销毁无资源残留；复用已加载美术，不引入新玩法。 |

## 4. 验收标准

- AC-1：新Web包中两人/三人、普通怪/魔王截图均显示脚底落地；无常驻人物面板底色，背景原色，生命/护盾与敌人意图可读。
- AC-2：真实攻击、定向防御、受击及阵亡使条形和数字跟随Snapshot；护盾超出条形参考量时仍显示真实数字，无隐式上限或状态截断。
- AC-3：至少五张手牌默认可观察右盖左，实际鼠标逐张悬停可完整阅读；移出恢复；悬停前后Snapshot与存档字节不变。
- AC-4：重叠处点击命中最上层，悬停和选中突出不抢走队友/敌人目标点击；不可用牌仍可查看但不能出牌。快速移动和边缘切换无持续抖动。
- AC-5：出牌后手牌变化、结束回合、读档、切页与销毁不留下悬停状态/监听/补间；加载失败文字回退通过。
- AC-6：既有配置及玩法回归通过，受影响类型/分层/诊断检查通过；新Web构建包真实鼠标回归及专项截图通过。预览不得代替新包，历史001/002/003证据不覆盖。
- AC-7：新Web包左下角四色能量图标及数字匹配Snapshot，白色图标使用指定素材；无顶部重复能量或手牌遮挡；默认及选中卡牌时无常驻选牌操作提示，能量不足等反馈仍有效；白色图标单独失败及全部图片失败均能显示四色数字。
- AC-8：默认配置下两人/三人队伍人物朝左，普通怪/魔王朝右；仅怪物画像水平镜像，生命/护盾/意图文字不镜像；方向切换不改原图内容与UUID，素材落地清理遵循AC-9；真实鼠标选牌与目标点击回归通过。
- AC-9：当前五素材调整前均有可恢复备份；清理不改变alpha≥16主体像素的颜色与相对位置，UUID保持。素材脚底中心距画布底部中央误差≤1像素，导入后整图边界和留白保留；新Web包两人/三人及普通怪/魔王脚底与既有阴影相接，史莱姆身体底部不再明显悬空。素材整理不引入接地点机制，独立显示高度遵循AC-10，状态和存档不变。
- AC-10：五类目标可独立调整显示高度；新Web包默认绿色骑士270、红蓝245，普通怪199、魔王229（设计坐标单位），显示高度与配置误差≤1，宽高比不变，脚底基线不变、文字避开头部；修改单项不改其他目标或Snapshot/存档。非法高度被拒绝，缺省高度兼容旧显示；两人/三人、阵亡与读档回归通过。

- AC-11：项目卡框与用户确认图片内容一致，原图及导入设置有可恢复备份，资源UUID/路径不变；新Web包卡框加载成功，默认与悬停手牌显示新名称栏，名称保持动态文字。
- AC-12：新Web包卡名位于中间名称栏，左上费用图标与卡牌所需颜色匹配、数字位于图标内；现有单色卡只显示真实单项费用。隔离表现测试四项按红绿蓝白纵排，0及小数保留，多项收回为单项不残留；单图失败有颜色/数字回退，整体失败仍有文字卡，销毁清空费用Sprite引用。悬停/选中/支付/存档不变，未引入多色费用玩法。

- AC-13：新Web包选角色页三名当前立绘与颜色配置一致、朝向正确、文字不重叠，真实选择顺序/确认/旧档继续有效且未确认不写档；战后选牌显示新卡框、名称栏和费用图标，点击任一卡只增加对应一张并返回地图。单图/全部图/配置失败时可读文字回退，共用加载数仍13，销毁清空两个选择页的Sprite引用；默认及改值配置回归通过。

## 5. 已确认的护盾显示约定

护盾没有玩法最大值。用户已确认以角色最大生命作为固定的条形显示参照，显示宽度饱和但数字始终精确；该约定只影响显示，不增加格挡上限。
