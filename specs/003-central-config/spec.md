下游：plan.md / tasks.md

## 1. 目标

将现有全局参数、角色起始牌、卡牌、敌人和美术映射统一集中管理，使后续调整现有数值与起始牌张数不必修改业务代码。本轮仅迁移已有默认内容，保持游戏结果不变。

## 2. 非目标

不把起始牌从每人3张改成5张；不增加卡牌效果、角色个体生命或产能、难度系统、敌人行为、奖励颜色、角色数量或新美术。不引入热更新、远程配置、通用编辑器、外部依赖；不变更存档格式或平台实现；提交和推送须用户授权；2026-11-20用户已明确授权单独提交003并push。

## 3. 用户故事

- US-1：开发者能够集中找到并修改全局参数、角色与起始牌、卡牌、敌人和美术对应关系。
- US-2：玩家看到的组队参数与实际新局一致，不出现展示3张但实际5张等重复硬编码问题。
- US-3：修改默认内容后，新局使用新值；继续旧局仍保留当时的玩法参数、卡牌和队伍顺序。
- US-4：配置错误能得到明确提示，不会悄悄创建错误的新局或覆盖已有存档。

## 4. 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 全局参数、角色、卡牌、敌人与美术映射五类配置统一管理；相同玩法值不再同时由组件属性和配置决定。 |
| FR-2 | 保持现有默认种子、层数、队伍、卡牌重复数量、定义顺序、数值、美术与镜像结果；实际队伍继续按玩家点击顺序生成。 |
| FR-3 | 起始牌允许已有卡牌ID的重复列表，张数由列表决定；卡牌效果只接受已有攻击/防御。组队显示从实际配置派生。 |
| FR-4 | 校验字段类型、数值、标识唯一性、已支持效果和跨配置引用；重复起始牌是合法数据，不得当作重复ID错误。错误提示明确到所属类别与字段。 |
| FR-5 | 加载完成前不能开始新局；加载或校验失败禁止新建，保留有效旧存档，不自动删除或覆盖。图片加载失败仍保持文字回退。 |
| FR-6 | 新局使用当前配置；有效旧局使用其已保存的玩法参数，不因读取新配置改变旧局或后续随机结果。当前美术配置不成为旧局玩法状态。 |
| FR-7 | 现有点击路径、共享牌组、能量规则、奖励规则、三层流程及战斗表现保持不变；不修改001/002历史证据。 |

## 5. 验收标准

- AC-1：现有默认配置迁移前后关键值、数组顺序、重复起始牌与生成的新局一致；原两人6张、三人9张保持不变，具备黄金断言。
- AC-2：只修改受支持的配置项后，新局和组队展示出现对应变化；初始牌重复数量生效，无须修改业务代码。测试变更不保留在生产默认配置中。
- AC-3：非法结构、重复定义ID、断引用、未知效果、非法数值或不完整美术映射均被拒绝，提示具体字段；错误配置不覆盖存档。
- AC-4：当前配置改变后，已有局的玩法参数、卡牌、队伍顺序、继续游玩的随机结果仍与原存档一致。坏配置时旧存档仍可继续，并使用可读的文字回退；读取和选队不改变存档字节。
- AC-5：正常加载、加载失败及组件提前销毁有测试或隔离浏览器证据；初始化只执行一次，无迟到访问或遗留持有引用。
- AC-6：已有回归与新增配置测试、全部assets严格类型、分层检查通过；修改源码无新增诊断。包含新配置的Web新构建包中真实鼠标回归和美术生命周期通过，正常控制台/网络无错误。不得以旧包或编辑器预览代替新包，不宣称根tsc或真实三端通过。

## 6. 开放问题

配置表编辑工具、版本迁移、更大卡池的表现预算、超过现有能力的新效果均留给后续feature。本轮不冻结未验证的平台参数。
