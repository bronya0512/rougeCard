# Spec 002：战斗占位美术接入

状态：Confirmed（2026-11-19 用户确认计划并授权执行）
阶段：P2 占位战斗切片
上游：constitution.md §1 占位范围、C-1/C-3/C-4/C-6/C-7、§4、§7；001-core-loop 已验收玩法；specs/worldbuilding.md
下游：plan.md / tasks.md

## 1. 目标

将已导入的 12 张占位图片用于现有战斗页，验证三人布局、卡牌插画组合、信息可读性和鼠标交互。前期仍呈现奇幻冒险，不制作程序报错或漏洞演出。

## 2. 非目标

不改玩法、角色池、组队人数、数值、输入语义、存档；不扩展组队、地图、奖励或结算美术；不引入终版美术、动画、音效、新敌人行为或平台适配。用户于2026-11-19人工验收通过，并授权提交和推送本feature相关改动。

## 3. 用户故事

- US-1：玩家在战斗中能辨认队伍颜色、生命、格挡、阵亡及敌人意图。
- US-2：玩家能看到攻击或防御插画与卡牌底板组合，读到名称、费用、效果，并按原方式选牌和指定目标。
- US-3：加载占位图失败时玩家仍能使用原有文字与色块界面。

## 4. 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 三色角色按实际队伍与顺序显示，敌左我右；蓝色角色与魔王调整为朝向对手；图像等比显示，阵亡可辨认。 |
| FR-2 | 普通战斗显示普通怪，boss 节点显示魔王；生命与意图保持动态且清晰。 |
| FR-3 | 攻击/防御图片作为卡牌插画放在底板透明窗口后方，限制到窗口范围，不露出卡框外围；名称、颜色费用、效果和可出牌/选中状态保持动态。 |
| FR-4 | 使用战斗背景与红绿蓝能量图，白色能量保持文字表达；背景不遮挡操作信息。 |
| FR-5 | 图像加载不推进状态或写存档；加载失败回退文字色块；组件销毁后不再更新已销毁节点，不遗留由其持有的资源引用。 |
| FR-6 | 原有选卡、错误目标拒绝、定向防御、结束回合、读档与楼层推进继续有效；战斗之外保持原页面。 |

## 5. 验收标准

- AC-1：真实 Web 新构建包中可观察两人/三人、普通怪/魔王、三色能量，图片与当前队伍和节点对应；保留截图与只读运行记录。
- AC-2：攻击与防御卡均有窗口内插画和底板，文字、颜色费用、效果可读；选中与不可用可辨认；透明外围无插画泄出。
- AC-3：真实鼠标选卡不改变 Snapshot/存档，攻击点敌人、防御点存活队友生效，错误目标不推进；既有完整 Web 回归通过。
- AC-4：战斗读档后图片与存档队伍/敌人/卡牌一致；重开不扩展其他页面美术。
- AC-5：受控资源加载失败仍可使用文字界面；加载前销毁及正常销毁不发生迟到节点访问或引用泄漏，保留测试/浏览器证据。
- AC-6：已有核心/会话/适配器测试与严格类型、分层检查通过；改动源码诊断无新增错误。新 Web 构建成功且控制台/网络正常路径无错误。不得用旧包或编辑器预览代替新包；不得宣称根 tsc 或真实三端通过。

## 6. 开放问题

完整资源规格、终版风格、移动端预算与批量资源优化不在本任务中冻结；当前使用资源的原始尺寸与既有导入设置。
