# Spec 001：核心循环（Core Loop）

状态：Draft（玩法已定，本 spec 范围为 M1 最小可玩版本）
里程碑：M1
上游：`constitution.md`（依赖 C-3、C-4、C-5、C-6、C-7 与 §4 确定性约束）
下游：`plan.md` / `tasks.md`

## 1. 背景与目标

验证「同一个 Cocos 工程、同一份纯 TS 核心逻辑，能同时跑在 H5、微信小游戏、Windows」这一架构假设，并产出可在浏览器里玩通一局的 H5 demo。

题材：类杀戮尖塔的卡牌肉鸽。一局由局外跑图与局内战斗交替组成；全队生命值归 0 失败，击败最终 boss 胜利。

本 spec 只实现 §1.2 的最小可玩版本；§1.1 为已确认的完整设定，由后续 feature 分批承接，记录在此以免后续返工。

### 1.1 完整玩法设定（已确认，跨 feature 共用）

**跑图**

- 六边形网格，层数可配置为 3–5 层（2026-11-17 用户补充）；每层 1 个起点（位于该层中心）、1–3 个终点；每局随机生成。
- 击败当前层 boss 后进入下一层的起点；只有击败最后一层 boss 才胜利结算。层间保持队伍生命/阵亡状态与成长后的牌组，地图访问记录按层区分，当前楼层及进度纳入存档；不因换层自动满血或复活。
- 每个格子都是节点，空格即无事件；可走回头路，已访问节点不再触发事件。
- 同层不同终点必须有差异（如影响下一层的精英比例或奖励倾向）；最后一层终点只有 boss。
- 节点类型：普通战斗、精英、休息、商店、事件、宝箱、boss。
- 每层有步数上限与迷雾（机制参考明日方舟「黑流树海」，名称、文案、美术不照搬）。参数可配置，默认值：

| 层 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 步数上限 | 5 | 7 | 9 | 7 | 5 |
| 半径 | 3 | 5 | 6 | 5 | 3 |

- 生成约束：任意 seed 下，起点到该层每个终点的最短路径不超过该层步数上限。

**队伍与战斗**

- 开局从角色池选 2–3 个角色组队，局内不换人；回合制。
- 每个角色单独计生命值与格挡；全队阵亡才失败；阵亡状态延续到后续战斗，休息点可复活。
- 属性 / 能量颜色：红、绿、蓝、白。玩家回合开始时，每个存活角色产出自身颜色能量（每人 1–2 点，可配置）；阵亡角色不产出；未用完的能量在回合结束时清空。
- 白色能量为通用能量，可支付任意颜色费用。
- 全队共用一套牌组；牌只按颜色付费，不绑定角色。
- 阵亡角色的牌保留在牌组中（惩罚设计，防止主动牺牲角色压缩卡组形成无限循环）；规避方式为配置同色角色或使用白色能量。
- 敌人行动前显示意图；攻击目标按确定规则选择，不随机。
- 属性克制、敌人属性首版不做。

**奖励与背包**

- 起始卡组由所选角色各自的起始牌合成。
- 战斗胜利后三选一加入牌组，候选只来自队伍现有颜色。
- 背包包含遗物与移动道具；移动道具一次性使用，背包有容量上限，可从商店、宝箱、事件获得。
- 不做战斗内消耗品。

### 1.2 本 spec 范围（M1 最小可玩版本）

- 地图：层数配置为3/4/5（默认3），各层半径2；起点在中心；每层1个终点（boss）位于最外圈；非最终层boss击败后直接进入下一层起点，最后一层才胜利。层间保留生命、阵亡和成长牌组，清理战斗临时格挡/能量，未用手牌归弃牌堆；不自动回血、不额外给boss奖励。节点类型只有普通战斗、休息、boss；无步数上限，无迷雾。旧版单层存档仅按单层语义迁移，不改写成三层进度。
- 队伍：固定红、蓝 2 个角色，各自每回合产出 1 点自身颜色能量。
- 战斗：§1.1 的颜色付费、阵亡卡手、全灭失败规则全部生效；防御牌的格挡由玩家选择目标队友；敌人攻击最左侧存活角色。
- 页面与操作：地图与战斗为游戏内独立页面，不新开浏览器窗口；战斗页敌方位于左侧、我方位于右侧，我方内部保持原队伍顺序。左键选卡，再左键点击怪物使用攻击牌／点击存活队友使用防御牌。地图左键节点弹出信息，右键节点移动；相邻与节点触发规则不变。
- 奖励：普通战斗胜利后三选一（红 / 蓝牌池）。
- 不提供白色能量来源，但白色付费规则需实现并由单测覆盖。
- 具体数值（生命、伤害、格挡、每回合抽牌数、节点类型配比、休息恢复量）均为可配置项。

## 2. 非目标

- 完整 5 层跑图、1–3 个终点及终点差异、步数上限、迷雾（后续跑图 feature）。
- 3 人队伍、角色选择、绿 / 白角色、属性克制、敌人属性（后续战斗 feature）。
- 精英、商店、事件、宝箱节点；遗物、移动道具、背包（后续背包 feature）。
- 卡牌与敌人内容规模化、数值平衡、终版美术、音效资源。
- 联网、排行榜服务端、账号、内购、成就（成就属 M3 范围）。
- 平台专属优化（分包、性能调优、Steamworks 接入）分别在 M2 / M3 处理。

## 3. 用户故事

- US-1：作为玩家，我能从入口开始一局，看到随机生成的六边形地图、当前位置与队伍状态。
- US-2：作为玩家，我能在地图上移动到相邻格子并触发节点（战斗 / 休息 / boss），已访问节点不重复触发。
- US-3：作为玩家，我在战斗中用两个角色产出的彩色能量出牌，每次操作都有即时、可预期的反馈，并能在行动前看到敌人意图。
- US-4：作为玩家，角色阵亡会持续影响后续战斗（不再产出能量、他的牌卡手），直到我在休息点复活他。
- US-5：作为玩家，击败 boss 进入胜利结算，全队阵亡进入失败结算，结算后不能继续操作。
- US-6：作为玩家，退出后重新进入能读回本局进度。
- US-7：作为开发者，同一 seed 与输入序列在三个平台产出完全一致的结果，便于排查问题。

## 4. 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 开始：从入口进入一局，`core/` 由 seed 与配置初始化为确定的初始 `GameState`（地图、队伍、起始卡组）。 |
| FR-2 | 输入：`game/` 将平台输入转换为 `GameInput` 交给 `core/`，不得直接修改状态。输入至少包括：移动、出牌（含目标）、结束回合、选择奖励。 |
| FR-3 | 推进：`core/` 按确定性规则推进状态，产出可供渲染的 `Snapshot`；非法输入被拒绝且状态不变。 |
| FR-4 | 结算：全队阵亡进入失败结算；最后一层 boss 生命归 0 进入胜利结算；结算后状态冻结，后续输入被拒绝。 |
| FR-5 | 存档：本局进度经 `Storage` 适配器写入，重进可读回并恢复。 |
| FR-6 | 三端一致：Web / 微信小游戏 / Windows 对同一 seed 与输入序列得到相同 `Snapshot`。 |
| FR-7 | 平台隔离：`assets/core/`、`assets/game/` 中不出现平台专属 API。 |
| FR-8 | 地图生成：按 seed 生成 §1.2 地图；起点在中心，唯一 boss 在最外圈，节点类型数量符合配置。 |
| FR-9 | 移动：只能移动到相邻六边形格子；进入未访问节点触发其事件，已访问节点不再触发；战斗中不可移动。 |
| FR-10 | 能量：玩家回合开始时每个存活角色产出配置数量的自身颜色能量；阵亡角色不产出；回合结束时未用能量清空。 |
| FR-11 | 出牌：牌只按颜色费用支付，同色能量优先，白色能量补足差额；能量不足时出牌被拒绝。 |
| FR-12 | 牌堆：回合开始抽配置数量的牌；抽牌堆为空时将弃牌堆洗入抽牌堆；回合结束时手牌进入弃牌堆。 |
| FR-13 | 阵亡：生命归 0 的角色阵亡，不再产出能量、不再成为敌方目标；其牌仍保留在牌组循环中；阵亡状态延续到后续战斗。 |
| FR-14 | 敌人：敌人意图在玩家行动前确定并在 `Snapshot` 中展示；攻击目标为最左侧存活角色。 |
| FR-15 | 格挡：防御牌由玩家指定一名存活队友获得格挡；伤害先扣格挡再扣生命；格挡在玩家下一回合开始时清零。 |
| FR-16 | 休息：进入休息节点时复活全部阵亡角色，并按配置恢复生命。 |
| FR-17 | 奖励：普通战斗胜利后提供 3 张来自红 / 蓝牌池的候选牌，玩家选择 1 张加入牌组。 |
| FR-18 | 桌面交互：地图左键查看节点信息、右键请求移动；战斗进入独立页面（敌左我右），先左键选卡再点击合法目标施放。选卡／查看信息不推进状态、不消耗资源、不存档；可切换或取消选卡，错误目标不施放。结束回合、奖励选择与重开提供鼠标按钮；进度恢复后按当前阶段进入对应页面。 |
| FR-19 | 多层地图：新局可配置3/4/5层、默认3；逐层击败boss前进，最终boss才胜利。层间保留HP/阵亡及全部牌UID，清空战斗能量/格挡、未用手牌归弃牌堆，不回血、不增加boss奖励。各层地图访问状态独立，当前楼层/已完成地图/注入RNG状态进入存档；旧单层存档按原单层语义迁移。 |

## 5. 验收标准（可判定）

- AC-1：给定 seed、配置与输入序列 S1，三端序列化后的 `Snapshot` 逐字段一致；`core/` 单元测试包含该用例。
- AC-2：Web 构建产物可通过本地静态服务器访问，在浏览器中完成「开始 → 地图移动 → 普通战斗 → 选奖励 → boss 战 → 结算」全流程，浏览器控制台无错误。
- AC-3：退出后重新进入，读回的本局状态与退出前最近一次存档一致（存档时机见 Q-8）。
- AC-4：全仓搜索 `wx.`、`steam`、`window.`、`document.`，在 `assets/core/`、`assets/game/` 中无命中（白名单须在 `plan.md` 登记）。
- AC-5：`core/` 单元测试全部通过，并覆盖 AC-7 ~ AC-14 与 FR-4「结算后拒绝输入」。
- AC-6：`tasks.md` 中 M0 阻塞项全部完成（宪法 v0.2：Web + Windows 两端打通；微信小游戏 T003 延后、不计入 M0 阻塞），且 `plan.md` 状态为 Confirmed（对应宪法 C-7）。
- AC-7（地图）：同一 seed 两次生成的地图逐格一致；起点在中心；恰有 1 个 boss 且位于最外圈；各节点类型数量符合配置；任取 10 个 seed 生成的地图不全相同。
- AC-8（移动）：移动到非相邻格被拒绝；重复进入已访问节点不触发事件；战斗中的移动输入被拒绝。
- AC-9（能量）：双角色存活时回合开始得到 1 红 + 1 蓝；任一角色阵亡后只得到另一色；回合结束后未用能量为 0。
- AC-10（付费）：单测覆盖「同色足够可出」「同色不足但白色补足可出」「能量不足被拒绝且状态不变」三种情况。
- AC-11（阵亡）：红色角色阵亡后，红色牌仍在抽牌堆 / 弃牌堆 / 手牌中且牌组总数不变；无白色能量时红色牌出牌被拒绝；阵亡状态在下一场战斗保留，进入休息节点后复活。
- AC-12（敌人与格挡）：玩家出牌前 `Snapshot` 已包含敌人意图；敌人攻击命中最左侧存活角色；格挡只加在玩家指定的队友身上，且先于生命扣除。
- AC-13（结算与奖励）：全队阵亡进入失败结算；最后一层 boss 生命归 0 进入胜利结算；普通战斗胜利后出现 3 张红 / 蓝候选牌，选择后牌组数量 +1。
- AC-14（牌堆）：抽牌堆为空时弃牌堆洗回抽牌堆；同一 seed 与输入序列下洗牌顺序一致。
- AC-15（页面）：进入战斗隐藏大地图并显示独立战斗页，敌左我右，我方显示顺序仍与原攻击目标规则一致；选奖励后回到地图，战斗存档重进后直接显示战斗页，不新开浏览器窗口。
- AC-16（两步出牌）：左键选卡显示高亮，不改变 Snapshot、能量或存档；选攻击牌后点怪物才生效，选防御牌后点存活队友才生效；错误目标／阵亡目标不施放。可取消或切换所选牌；出牌成功、回合结束或阶段变化后清理所选牌。
- AC-17（地图鼠标）：左键节点显示类型、坐标、访问状态与是否可移动且不移动、不存档；右键相邻节点才请求移动，非相邻移动被拒绝；游戏画布右键不弹浏览器菜单。
- AC-18（鼠标全流程）：真实 Web 包仅通过鼠标完成地图移动→普通战斗→奖励选择→boss→结算并重开；结束回合按钮可用、控制台无错误；键盘不作为必需操作。
- AC-19（楼层推进）：3/4/5层配置均有效，默认3；从第1层开始，非最终层boss击败直接进入下一层中心且不结算/不给普通战斗奖励，最后boss才胜利；非法层数拒绝。楼层推进revision连续，最终结算冻结。
- AC-20（层间延续）：切层保留HP/死亡与全部牌UID（含奖励和消耗区），未用手牌归弃牌堆，能量/格挡清空；不重初始化队伍/牌组。下一层仅起点已访问，历史地图不因当前层访问改变；地图UI和楼层指示正确刷新。
- AC-21（楼层存档与确定性）：击败boss前后读档恢复楼层/地图/队伍/牌组与RNG，恢复后的后续地图和战斗与未中断序列一致。旧schema1有效单层档迁移后保持单层进度/胜负，损坏或非法楼层数据安全回退新局；不得把旧胜利变成多层中途胜利。
